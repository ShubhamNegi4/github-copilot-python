# Project Instructions for Copilot

## Project Overview
This is a Sudoku Challenge web application built with Flask and vanilla JavaScript. The app generates playable Sudoku puzzles, provides hints, validates solutions, tracks time, and maintains a Top 10 leaderboard of fastest solves.

## Tech Stack
- **Backend:** Python 3.11, Flask
- **Frontend:** Vanilla JavaScript (ES6+), CSS3 (CSS custom properties for dark mode)
- **Testing:** pytest
- **Puzzle Generation:** Backtracking algorithm with customizable difficulty levels (easy, medium, hard)

## Key Architecture Decisions
- **Game State Management:** All game state (puzzle, solution, difficulty) is stored server-side in the `CURRENT` dictionary to prevent cheating
- **Sudoku Representation:** 9x9 2D list; `0` represents an empty cell
- **Leaderboard Storage:** Top 10 scores stored in browser `localStorage` with sorting by time, then hints used
- **Theme Persistence:** Dark mode preference saved in `localStorage`

## Coding Conventions

### Python
- Use type hints on all function signatures
- Docstrings for all functions with complex logic
- Validate all JSON request data before processing
- Use constants from `sudoku_logic` module (SIZE=9, EMPTY=0, BOX_SIZE=3)
- Return Sudoku puzzles as 2D lists with 0 representing empty cells

### JavaScript
- Use `const` by default; only use `let` when reassignment is needed
- Document global variables at the top (solution, difficulty, timerId, elapsedSeconds, hintsUsed)
- Prefix DOM query selectors with descriptive names (e.g., `inputs`, `scoreboard`)
- Store data in `localStorage` with keys prefixed by module name (e.g., `sudoku-theme`, `sudoku-top-10`)
- Use event delegation where appropriate; attach event listeners in the `load` event handler
- Format 1-based messages for users ("row X, column Y") while using 0-based indexing internally

### CSS
- Define color variables in `:root` and `body[data-theme='dark']`
- Use CSS custom properties (variables) for theming; avoid hardcoded colors
- Responsive design: use `clamp()` for fluid sizing where appropriate
- Maintain accessibility: sufficient color contrast, proper focus states, ARIA labels

## Game Logic & Rules

### Puzzle Generation
- Sudoku is valid when each row, column, and 3x3 box contains digits 1-9 exactly once
- Starting clues per difficulty: easy (40), medium (32), hard (26)
- After generating a complete valid solution, randomly remove cells to create the puzzle

### Solution Validation
- User submission must exactly match the `solution` stored server-side
- When checking, compare user board against `CURRENT["solution"]`; return all incorrect cell coordinates
- Empty cells and missing values count as incorrect
- A puzzle is "solved" only when user fills all cells correctly AND has no incorrect entries

### Hint Behavior
- Fill one random empty cell from the original puzzle with its solution value
- Mark hint cells with the `hint` class and disable them so they can't be edited
- Track total hints used during the game
- If all cells are filled, return an error ("No empty cells left")

### Leaderboard
- Top 10 fastest times by difficulty level
- Sort primary by elapsed time (ascending), secondary by hints used (ascending)
- Saved as array of objects: `{ name, time (seconds), difficulty, hints }`
- Display as ordered list with rank, player name, difficulty, and formatted time (MM:SS)

## Testing
- Run tests: `pytest test_sudoku_logic.py`
- Current tests cover: board creation, safety checking, empty cell finding, board filling, puzzle generation
- Manual testing: start server with `python app.py` and navigate to `http://localhost:5000`

## Development Workflow
1. For backend changes, restart Flask app
2. For frontend changes, hard refresh browser (Cmd+Shift+R on Mac)
3. For puzzle logic changes, run tests to validate
4. When adding new features, ensure they work across light and dark modes

## Known Limitations & Future Improvements
- No user authentication; leaderboard is device-local
- No persistent database; leaderboard resets on browser data clear
- Difficulty affects only the number of starting clues, not algorithm complexity
- No undo/redo functionality
- No puzzle sharing or difficulty estimation after generation
